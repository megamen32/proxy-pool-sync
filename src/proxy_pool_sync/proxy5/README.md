# proxy5-registry — единый реестр прокси proxy5

Одно место, где живёт правда о пуле proxy5: какие адреса нам вообще
выдавали, из какой они страны, кому в whitelist можно ходить и как пул
ротируется. Снаружи — MCP-сервис, которым управляют агенты.

## Зачем

Пул proxy5 — это 2000 адресов на порту 8085, которые провайдер ротирует.
До этого:

* **история терялась** — кабинет отдаёт только текущий состав `/ips`, а
  прежние адреса из ротаций пропадали;
* **страна была ни у кого не записана** — поле `country_code` в
  `db_video_stats.proxyn` пусто у всех 6000 строк, поэтому фильтр
  `?country=non_ru` в экспорте фактически ничего не отсекал, и TGC с Out of
  Find Client получали RU-адреса вместе с остальными;
* **каждый потребитель тянул своё** — Video Watching ходил в кабинет сам,
  TGC и Out of Find Client получали готовый экспорт и жили с чужим
  расписанием ротации.

## Что внутри

| Модуль | Что делает |
|---|---|
| `core.py` | Разбор ответа кабинета, порт по протоколу, слияние снимка пула с инвентарём, сводка по странам. Без сети и без БД. |
| `cabinet.py` | HTTP/MCP-клиент кабинета: пул, whitelist, вызовы инструментов MCP-кабинета, GeoIP-резолвер по локальной базе. |
| `inventory.py` | Хранилище инвентаря в SQLite: все когда-либо выданные адреса, страна, даты, «действует / история». |
| `sync.py` | Разовая сверка пула с инвентарём + гео-сверка. Только чтение кабинета. |
| `service.py` | MCP-сервис (stdio) поверх всего перечисленного. |

## Инструменты MCP

| Инструмент | Что делает |
|---|---|
| `proxy5_sync_inventory` | Снять текущий пул кабинета и внести в инвентарь; вернуть новые/исчезнувшие и гео. |
| `proxy5_inventory_summary` | Сводка: всего адресов за всю историю, действующих, в истории, разбивка по странам. |
| `proxy5_inventory_list` | Список адресов: страна, статус, первое появление, число ротаций. |
| `proxy5_geo_check` | Сверка стран: кабинет (MaxMind провайдера) против локального GeoLite2-файла, с вердиктом по каждому адресу. |
| `proxy5_whitelist` | Текущий whitelist egress-IP с лимитами, conn_cap и суммой; предупреждение, если хоп из реестра в whitelist отсутствует. |
| `proxy5_set_limits` | Задать `conn_limit` по IP с пересчётом суммы. Отказ, если Σ ≠ conn_cap или лимит < 1. |
| `proxy5_add_ip` / `proxy5_remove_ip` | Добавить/убрать egress-IP из whitelist. |
| `proxy5_hops` | Реестр хопов: кто обязан быть в whitelist, кто выключен, кто основной. |
| `proxy5_cabinet_tools` | Список 54 инструментов MCP-кабинета провайдера. |

## Инвариант whitelist

Провайдер отклоняет план лимитов, если сумма не равна `conn_cap`, а лимит
для IP меньше 1. `proxy5_set_limits` считает сумму сам и отказывается до
записи, а после записи перечитывает whitelist и сверяет результат. Поэтому
ручная правка лимитов не может молча разъехаться с остальными IP.

Сейчас в whitelist ровно три egress-IP:

| IP | кто | conn_limit |
|---|---|---|
| `95.165.165.65` | домашний WAN (100/88) | 4425 |
| `31.76.43.193` | FIN, основной хоп | 1500 |
| `212.192.31.128` | vpn2, резервный хоп | 75 |

`185.240.120.152` (VUSA) выключен приказом владельца 20.10 и в whitelist не
входит — пул такому egress не отвечает.

## Развёртывание

```bash
# каталог данных
sudo mkdir -p /var/lib/proxy5-registry
sudo chown roomhacker:roomhacker /var/lib/proxy5-registry
sudo chmod 750 /var/lib/proxy5-registry

# юниты
sudo cp deploy/proxy5-registry-sync.{service,timer} /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now proxy5-registry-sync.timer
```

Таймер сверяет пул с инвентарём каждые 10 минут. Синкер только читает
кабинет; запись в whitelist — исключительно через MCP-инструменты и всегда
по явному вызову.

## Пути и секреты

| Что | Где |
|---|---|
| Ключ кабинета | `/etc/gptadmin/proxy5.headers` (0640 root:roomhacker) либо `/opt/rutube/state/server/proxy5-mcp-api.key` (0600 roomhacker) |
| GeoIP-база | `/home/roomhacker/.cloakbrowser/geoip/GeoLite2-City.mmdb` |
| Реестр хопов | `video_watching/scripts/ops/proxy5_hops.py` (переопределяется `PROXY5_HOPS_FILE`) |
| Инвентарь | `/var/lib/proxy5-registry/inventory.db` (0640) |
| Egress к кабинету | `socks5h://127.0.0.1:30881` (`PROXY5_IPS_EGRESS`) |

Токен кабинета не попадает в argv, журнал и ответы инструментов: он
читается из защищённого файла и уходит в заголовок запроса.

## Особенности кабинета

* `/ips` из датацентра отвечает минуты и требует egress-маршрута — поэтому
  пул берётся через curl с `--proxy` и большим бюджетом времени
  (`Cabinet.pool_via_egress`). Прямой путь с коротким таймаутом не годится.
* `/ips` отдаёт страну по каждому адресу (`geo_source: maxmind`) и тип
  протокола. Порт выводится из типа: `http` → 8085, `socks5` → 1085.
* Пишущие операции (add/remove/limits/rotate) есть только в MCP-кабинете,
  в REST их нет.

## Тесты

```bash
/opt/proxy-pool-sync/bin/python -m unittest discover -s tests -p "test_proxy5_registry.py"
```

13 кейсов: сохранение истории при ротации, идемпотентность повторного
снимка, приоритет гео кабинета над старым значением, разбор формата
кабинета, работа хранилища.

Зависимости `mcp` и `geoip2` стоят в `/opt/proxy-pool-sync` (venv без pip —
ставить через `uv pip install --python /opt/proxy-pool-sync/bin/python`).
